# LICENSE SYSTEM ARCHITECTURE
# ════════════════════════════════════════════════════════════════

This extension uses a robust, offline-capable cryptographic license system based on Ed25519 asymmetric signatures.

## Why this architecture?
Since this is a Chrome Extension with no user accounts, we need a way to issue licenses that cannot be easily spoofed or bypassed by simply editing local storage, while avoiding building a complex user auth system.

## Components

### 1. License Admin CLI (`license-admin/`)
This is a private Node.js tool that runs on your local machine.
- It holds the **Private Key**.
- It generates the license codes.
- It writes to a local SQLite database for record keeping.
- It can optionally notify the Supabase backend when a license is issued or revoked.

### 2. The Extension
The Chrome extension holds the **Public Key**.
- It can verify that a license code was generated by your private key.
- It stores the verified license in `chrome.storage.local`.
- It performs a daily background check against the Supabase server to see if the license has been revoked.
- If the server is offline, the extension fails open (allows access based on the valid cryptographic signature) up to the expiration date.

### 3. Supabase Edge Functions (`backend/`)
- Acts as a global revocation and device-limit check.
- When a user activates a license in the extension, the extension asks the server if the license is revoked or if the device limit is reached.
- The server responds with success or failure.

## The Cryptography
We use **Ed25519**.
1. When generating a license, the payload (JSON) is converted to bytes.
2. The payload is signed with the private key (resulting in a 64-byte signature).
3. The payload and signature are concatenated and Base64URL encoded.
4. The extension decodes the string, separates the signature and payload, and verifies the signature using the public key.

## Security Considerations
- The security of this entire system relies on keeping `license-admin/keys/private-key.b64` secret.
- If the private key is leaked, anyone can generate valid Pro licenses.
- The extension code is public (all Chrome extensions are easily unpacked). Thus, motivated attackers could modify the extension code to bypass the `EntitlementsService` checks. This is the reality of client-side software. The cryptographic license system prevents casual sharing of license keys and prevents non-technical users from bypassing the gate, which covers 99% of users.
